# Scalpel 1.0.0 Release Audit

## Scope

- Source and GitHub release only; no npm registry publish for this release.
- Primary transport remains local `stdio`.
- Canonical tool names and `scalpel_*` aliases remain backward compatible with
  `1.0.0-alpha.1`.
- Safety model version: `scalpel-safety-model-v1` (no longer a draft).

## Required Gates

- `pnpm validate`
- `pnpm audit`
- `pnpm hardening:all -- --expanded` on Windows
- `pnpm hardening:all -- --expanded` on Linux (`ubuntu-latest`, via GitHub
  Actions `hardening.yml`)
- `pnpm pack` followed by package smoke against the packed artifact
- Clean Git working tree at the tagged commit
- Green CI (`ci.yml`) on the tagged commit

## Claim Map Status At Release

All release-blocking claims in `scripts/hardening.ts`'s `claim_map` are
`implemented`:

- workspace-confined MCP file operations
- race-proof supported mutations before success
- crash-safe supported mutations with metadata-only recovery
- large-scale repository traversal and bounded operation evidence
- streaming large-file mutation
- cross-platform persistence evidence

## Changes Since `1.0.0-alpha.1`

- Streaming exact-replacement, append, and prepend for oversized existing
  UTF-8 files.
- Explicit `committed` / `aborted` / `unrecoverable` recovery classification
  with quarantine for corrupted/ambiguous records.
- Commit-time revalidation for `move`, plus explicit cross-device (`EXDEV`)
  detection and rejection.
- Structured `LOCK_TIMEOUT` error for live lock contention.
- Platform metadata and a parent-directory-fsync probe in every hardening
  report.
- CI workflows fixed (pnpm-not-found on every job; invalid `runner` context
  reference) and now include an automatic starter hardening lane.
- Mutating MCP eval track added and manually walked end-to-end over live tool
  calls.

## Release Correction

The first `v1.0.0` tag/release (commit `9648cd5`) was replaced minutes after
publishing, before any recorded downloads. It had three real defects, caught
in review: two release-note links used relative paths that don't resolve on
a GitHub release page, and the published tarball leaked an untracked, gitignored
internal review doc (`docs/REVIEW_ACTION_PLAN.md`) because `package.json`'s
`files` field whitelisted the whole `docs` directory, which is not filtered by
`.gitignore`. The tag was moved to `1ca8428` (fixes plus the dependency bumps
above) and all release assets were rebuilt and re-uploaded from that commit.

## Open Release Risks

- Malicious same-user modification after Scalpel reports success remains
  outside the safety claim by design (documented boundary, not a defect).
- Parent-directory `fsync` support is platform-dependent; Windows in this
  configuration does not support it, so strict durability mode's
  parent-directory flush is a best-effort, non-fatal warning there.
- `batch_edit`, `insert`, `delete_range`, and `replace_between_markers` do not
  stream; they still require the full file to fit within `maxReadBytes`.
- Hardening evidence covers Windows and one Linux distribution/kernel
  (Ubuntu on `ubuntu-latest`); other Unix-like filesystems are not
  individually proven.
