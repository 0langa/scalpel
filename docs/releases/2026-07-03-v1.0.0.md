# Scalpel 1.0.0

This is the first `1.0.0` release of Scalpel. It replaces the `1.0.0-alpha.1`
prerelease as the canonical stable release.

## Summary

Scalpel is a local-first MCP server for precise, atomic file editing over
`stdio`, aimed at coding agents that need predictable edits and explicit
failure behavior. `1.0.0` closes the alpha's headline blocker (large-file
mutation required a full in-memory read) and adds an explicit, auditable
recovery state machine, commit-time revalidation for `move`, and
cross-platform hardening evidence.

See [`docs/SAFETY_MODEL.md`](../SAFETY_MODEL.md) (safety model version
`scalpel-safety-model-v1`) for the full definitions behind every claim below.
This release does not use terms like "crash-safe" or "race-proof" outside the
boundaries that document defines.

## Installation

From a GitHub release asset:

```bash
npm install https://github.com/0langa/scalpel/releases/download/v1.0.0/scalpel-1.0.0.tgz
```

From source:

```bash
git clone https://github.com/0langa/scalpel.git
cd scalpel
pnpm install --frozen-lockfile
pnpm build
node dist/index.js
```

Codex CLI:

```bash
codex mcp add scalpel --env SCALPEL_ROOTS=/repo -- node /path/to/scalpel/dist/index.js
```

Scalpel is not published to the npm registry as of this release. Install from
the release tarball or from source.

## Safety Claim

Within the boundaries in `docs/SAFETY_MODEL.md`:

- **Crash-safe**: startup recovery classifies every pending transaction as
  `committed`, `aborted`, or `unrecoverable` from actual on-disk evidence, and
  never silently accepts unknown partial state. Corrupted or ambiguous records
  are quarantined instead of retried forever.
- **Race-proof**: in-process and cooperative multi-process mutations serialize
  on their target paths; external same-user replacement, deletion, directory
  replacement, or symlink replacement before commit fails closed; external
  modification after commit but before success is reported as a conflict;
  `move` revalidates source, destination, and destination parent directory
  immediately before renaming; path-lock contention with a live owner past
  `SCALPEL_LOCK_TIMEOUT_MS` returns `LOCK_TIMEOUT` instead of hanging.
- **Large-scale**: `patch`, `append`, and `prepend` stream oversized existing
  UTF-8 files above `maxReadBytes` through a bounded temp-file rewrite,
  including matches spanning read-chunk boundaries; oversized binary and
  non-UTF-8 files still fail closed before mutation; expanded public-corpus
  traversal (Express, Lodash, TypeScript, Kubernetes, LLVM) is proven with
  bounded scalpel-server RSS growth.
- **Recoverable**: transaction and recovery records are metadata-only and never
  contain file content.

## Evidence Summary

- `pnpm validate`: lint, typecheck, unit/integration tests, build, MCP smoke,
  and package smoke all pass on the final commit.
- `pnpm audit`: no known vulnerabilities.
- Expanded hardening (`pnpm hardening:all -- --expanded`), 96/96 required
  checks passed, on:
  - Windows (local run and GitHub Actions `windows-latest`)
  - Linux (GitHub Actions `ubuntu-latest`, kernel `6.17.0-1018-azure`)
- Platform probe results recorded per report: parent-directory `fsync` is
  unsupported (`EPERM`) on this Windows configuration and supported on Linux.
- CI is green on the final commit: Windows/Linux `pnpm validate`, package
  smoke, and the automatic starter hardening lane.
- Hardening reports and evidence are attached to this release as
  `scalpel-1.0.0-evidence.zip`, alongside `scalpel-1.0.0.tgz` and
  `SHA256SUMS.txt`.

## Supported Platforms

- Windows and at least one Unix-like filesystem (Linux), proven by the
  hardening reports above
- Node.js versions allowed by `package.json` (`>=22`)
- `stdio` MCP transport
- Workspace roots configured through `SCALPEL_ROOTS` or the process working
  directory

## Unsupported Cases

- Network filesystems and sync folders with non-standard rename/fsync
  semantics
- Cross-device moves: detected via `EXDEV` and rejected with
  `CROSS_DEVICE_MOVE_NOT_SUPPORTED` before any partial copy; no copy/delete
  fallback is implemented
- Malicious same-user modification after Scalpel has already reported success
- Kernel, disk, controller, antivirus, or filesystem bugs
- Binary byte-edit workflows and parser-aware semantic edits
- `batch_edit`, `insert`, `delete_range`, and `replace_between_markers` still
  require the full file to fit within `maxReadBytes`

## Migration Notes From `1.0.0-alpha.1`

- No breaking tool contract changes. Canonical tool names and `scalpel_*`
  aliases are unchanged.
- `patch` now streams oversized existing UTF-8 files instead of failing with
  `FILE_TOO_LARGE`; the streaming path omits the unified `diff` field (see
  `docs/TOOL_CONTRACTS.md`).
- `move` may now return `CROSS_DEVICE_MOVE_NOT_SUPPORTED` for cross-filesystem
  moves, and `CONCURRENCY_CONFLICT` for source/destination/parent-directory
  replacement detected immediately before commit; these were previously either
  unreachable or surfaced as unstructured errors.
- Path-lock timeouts now return a structured `LOCK_TIMEOUT` error instead of an
  unstructured thrown error.
- Existing `.scalpel-transactions` records from an alpha install are still
  compatible; startup recovery on `1.0.0` reads the same on-disk record shape
  and adds a `quarantine/` subdirectory for records it cannot safely resolve.
