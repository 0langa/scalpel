# Scalpel 1.1.0

Scalpel 1.1.0 is a reliability and security release on top of `1.0.0`. Edits
keep each file's line-ending style, an edit that grows a file past
`maxReadBytes` reports success instead of inviting a retry that applies it
twice, and startup recovery, link handling, and commit-time containment are
tightened.

See [`docs/SAFETY_MODEL.md`](https://github.com/0langa/scalpel/blob/v1.1.0/docs/SAFETY_MODEL.md)
(safety model version `scalpel-safety-model-v1`, unchanged) for the definitions
behind every safety statement below. This release does not widen the safety
claim of `1.0.0`; it closes gaps inside it.

## Highlights

- **Line endings.** Text that `patch`, `batch_edit`, `insert`,
  `replace_between_markers`, `append`, and `prepend` add to an existing file is
  written in that file's own style, including on the streaming paths: CRLF
  files get CRLF, LF files get LF. Mixed files and new files get the text as
  given, and an edit that changes nothing but line breaks still converts them
  on purpose. `create` writes its content exactly.
- **No double apply past `maxReadBytes`.** An `append`, `prepend`, `patch`, or
  `create` that grew a file past `maxReadBytes` was written but reported
  `FILE_TOO_LARGE`, so a client that retried applied it twice. Results now
  describe the file as Scalpel verified it right after the commit.
- **Security.**
  - Startup recovery only deletes Scalpel's own temp files beside a recorded
    target inside the configured roots, and never works through a linked
    transaction or quarantine directory.
  - `grep` no longer follows links out of the roots.
  - The journal is never appended through a symlink.
  - Owner-only files stay owner-only while their replacement is written.
  - Writes and moves recheck root containment and the target's identity when
    they commit.
  - The MCP SDK and its vulnerable transitive dependencies are updated.
- **Windows.** A rename blocked by antivirus, the indexer, a sync client, or an
  editor is retried for up to `SCALPEL_RENAME_RETRY_MS` (default 5000 ms)
  instead of failing with a raw `EPERM`.
- **Correctness.** A UTF-8 BOM stays at the start of the file; `insert` after a
  final line without a newline no longer glues the text onto it; streaming
  `patch` no longer splits an astral character across chunks; names that start
  with two dots are accepted; failed writes and moves clean up their records.

The full list is in
[`CHANGELOG.md`](https://github.com/0langa/scalpel/blob/v1.1.0/CHANGELOG.md).

## Installation

From the GitHub release asset:

```bash
npm install https://github.com/0langa/scalpel/releases/download/v1.1.0/scalpel-1.1.0.tgz
```

From source:

```bash
git clone https://github.com/0langa/scalpel.git
cd scalpel
pnpm install --frozen-lockfile
pnpm build
node dist/index.js
```

Scalpel is not published to the npm registry. Install from the release tarball
or from source.

## Upgrade Notes From `1.0.0`

- Tool names, schemas, result fields, and the `scalpel_*` aliases are
  unchanged. The new error codes `IO_ERROR` and `INTERNAL_ERROR` can appear,
  with the OS error code in `details.cause_code`.
- Within one `batch_edit`, a later edit that quotes LF text an earlier edit
  inserted into a CRLF file no longer matches. The batch fails with
  `ATOMIC_FAILURE` and the file is untouched.
- Read-only files are refused with `PERMISSION_DENIED` instead of being
  replaced.
- A ranged `read` whose range exceeds `maxReadBytes` fails with
  `FILE_TOO_LARGE`.
- `list_dir` hides hidden entries unless `allowHiddenPaths` is set and reports
  symlinked directories as links; `grep` lists links in `skipped_files`.
- On Windows, a call on a file another process holds open can take up to
  `SCALPEL_RENAME_RETRY_MS` before it fails.

## Known Gaps

- Text containing a NUL character is written, but the edit reports
  `CONCURRENCY_CONFLICT`, because the check after the commit classifies the new
  file as binary. Nothing is applied twice: text tools then refuse the file as
  binary, and `create` answers a retry with `FILE_EXISTS`.
- `create`, `append`, and `prepend` create missing parent directories before
  the commit-time containment check, so a junction swapped in during the call
  can still get empty directories created outside the roots. The file itself
  is never written there.
- The replacement file does not keep hard links, explicit ACLs, NTFS alternate
  data streams, Windows attributes other than read-only, or POSIX owner and
  group.
- Unchanged from `1.0.0`: malicious same-user modification after Scalpel
  reports success is outside the safety claim, parent-directory `fsync` support
  is platform-dependent, and `batch_edit`, `insert`, `delete_range`, and
  `replace_between_markers` still need the whole file within `maxReadBytes`.

## Evidence Summary

- `pnpm validate` (lint, typecheck, 179 tests with 9 platform skips, build, MCP
  smoke 33/33, package smoke) and `pnpm audit` pass on Windows.
- Starter hardening (`pnpm hardening:all`): 68 of 70 required checks pass on a
  local Windows machine. The two external symlink-swap race checks need the
  file-symlink privilege, which that machine lacks; they run in the Hardening
  workflow on GitHub-hosted Windows and Ubuntu runners.
- The expanded public-corpus hardening was last run for `1.0.0`.
