# Scalpel 1.1.0 Release Audit

## Scope

- Source and GitHub release only; no npm registry publish for this release.
- Primary transport remains local `stdio`.
- Tool names, schemas, result fields, and the `scalpel_*` aliases are unchanged
  from `1.0.0`. New error codes: `IO_ERROR` and `INTERNAL_ERROR`.
- Safety model version: `scalpel-safety-model-v1`, unchanged.

## Required Gates

- `pnpm validate`
- `pnpm audit`
- `pnpm hardening:all` (starter lane) on Windows and Linux, through the
  Hardening workflow on GitHub-hosted `windows-latest` and `ubuntu-latest`
- `pnpm pack` followed by package smoke (part of `pnpm validate`)
- Green CI (`ci.yml`) and Hardening on the tagged commit

## Evidence

- The release changes only the version, changelog, README, security policy, and
  release documents on top of `b38eef1` (merge of #21). CI and Hardening were
  green on `b38eef1` for Windows and Ubuntu:
  [CI 38644005801](https://github.com/0langa/scalpel/actions/runs/38644005801),
  [Hardening 38644005657](https://github.com/0langa/scalpel/actions/runs/38644005657).
- Local Windows run on the release tree (Node 22.23.2, pnpm 11.5.0):
  - `pnpm validate`: lint, typecheck, 179 tests passed with 9 platform skips,
    build, MCP smoke 33/33, package smoke at version `1.1.0`.
  - `pnpm audit`: no known vulnerabilities.
  - `pnpm hardening:all`: 68 of 70 required checks passed. The two failures are
    the external symlink-swap race checks, which plant a file symlink; this
    machine cannot create one (`EPERM` without the symlink privilege). The
    same two checks failed there on unchanged `main` during #20 and #21, and
    they pass on the hosted runners.
- Expanded public-corpus hardening (`pnpm hardening:all -- --expanded`) was not
  re-run for this release. The last expanded evidence is the `1.0.0` set.

## Changes Since `1.0.0`

- Audit fixes (#19): hardened startup recovery, link handling in `grep`,
  `list_dir`, and the journal, owner-only modes kept during writes, commit-time
  root containment and identity rechecks for writes and moves, Windows rename
  retries, BOM and final-line handling, bounded ranged reads, structured errors
  for unexpected exceptions, and the MCP SDK security update.
- Line-ending style preserved for edits, and the unused `memfs` dev dependency
  and placeholder workspace entries removed (#20).
- An edit that grows a file past `maxReadBytes` reports success instead of
  `FILE_TOO_LARGE` (#21).
- Dependency updates from Dependabot (`tsx`, `eslint`, `vitest` 5, `fast-check`,
  `actions/setup-node`).

## Known Gaps At Release

Listed in the release notes and `CHANGELOG.md`: NUL text reports
`CONCURRENCY_CONFLICT` after it is written, missing parent directories are
created before the containment check, and the replacement file does not keep
hard links, ACLs, alternate data streams, or POSIX owner and group.
