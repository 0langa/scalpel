# Support

Use GitHub issues for reproducible bugs, feature requests, and documentation
gaps.

Before filing an issue, include:

- Scalpel version or commit
- operating system
- Node.js version
- package manager version
- MCP client, if relevant
- `SCALPEL_ROOTS` shape, without private path details if needed
- command or tool call used
- expected result
- actual result

For safety issues, use `SECURITY.md` instead of a public issue.

For release readiness and hardening status, start with:

- `docs/project/FINAL_RELEASE_SPRINT.md`
- `docs/SAFETY_MODEL.md`
- `docs/HARDENING.md`
- `docs/releases/`
